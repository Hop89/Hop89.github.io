Perimeter: Network Security Analysis Tool

Overview

Perimeter is a Python-based network security analysis tool designed to extend the capabilities of Nmap by transforming raw scan data into actionable insights. While Nmap is widely used for discovering hosts and services on a network, its output often requires significant expertise to interpret effectively. Perimeter addresses this gap by introducing an additional analysis layer that evaluates risk, detects misconfigurations, and tracks changes in network security posture over time.

Rather than replacing Nmap, Perimeter builds directly on top of it, using its scan results as a foundation for deeper analysis. The tool focuses on making network security data more accessible and useful, particularly for identifying vulnerabilities, prioritizing issues, and understanding how a system evolves across multiple scans.

Project Motivation and Development

I began developing Perimeter as part of my broader interest in cybersecurity and defensive systems. While working with network scanning tools, I noticed that although collecting data is relatively straightforward, interpreting that data in a meaningful way is much more difficult. Tools like Nmap provide detailed information about hosts and services, but they do not directly answer questions about risk, priority, or how a system’s security is changing over time.

I wanted to build a tool that could bridge this gap by automatically interpreting scan results and presenting them in a more actionable way. Initially, Perimeter started as a simple wrapper around Nmap, but as I continued developing it, I expanded it into a modular system with dedicated components for parsing, analysis, storage, and trend evaluation. This evolution reflects my shift from writing small scripts to designing a more complete and structured security tool.

Technologies and Skills Developed

Developing Perimeter allowed me to deepen my experience with Python while also learning how to integrate external system tools into a larger application. I worked extensively with Nmap as the underlying scanning engine, and one of the key technical challenges I addressed was parsing its XML output into structured data that could be analyzed programmatically.

Through this process, I gained experience in designing modular systems, where different components handle scanning, parsing, analysis, and storage independently. This improved both the maintainability and scalability of the project. I also developed a command-line interface that supports multiple workflows, which required thinking carefully about usability and how users would interact with the tool.

In addition, I explored integrating AI-based analysis to enhance the interpretation of findings. This introduced me to working with APIs and combining traditional software logic with machine learning–based insights. Overall, this project strengthened my skills in system design, data processing, and building practical cybersecurity tools.

System Architecture

Perimeter is organized as a collection of modular components, each responsible for a specific part of the workflow. The command-line interface serves as the entry point, allowing users to initiate scans, analyze results, and review trends. Behind the scenes, a dedicated module handles the execution of Nmap scans, while another parses the resulting XML data into structured formats.

The analysis layer is responsible for evaluating findings and assigning risk scores based on predefined criteria. Storage is handled separately, with reports organized by IP address and timestamp to support historical tracking. Finally, the trend analysis component compares reports over time to identify patterns, improvements, or regressions in security posture.

This modular structure ensures that each part of the system can be developed and tested independently, while still contributing to a cohesive overall workflow.

Features and Capabilities

One of the central features of Perimeter is its ability to convert raw scan data into prioritized findings. Instead of presenting users with a list of open ports and services, the tool evaluates each result and assigns a level of severity. This allows users to quickly identify critical issues and focus their attention where it is most needed.

In addition to risk scoring, Perimeter includes mechanisms for detecting common misconfigurations, such as exposed services or unnecessary open ports. These checks help highlight potential weaknesses that may not be immediately obvious from the scan output alone.

Another key capability is the system’s support for historical tracking. Reports are stored in a structured format, allowing multiple scans of the same target to be compared over time. This enables users to observe how a network evolves, whether security measures are effective, and how changes impact overall risk.

Building on this, the trend analysis functionality provides a higher-level view of security posture. By comparing reports, the tool can identify new findings, resolved issues, and changes in severity. This makes it possible to detect both improvements and regressions, offering insight into the effectiveness of security practices.

An optional feature of the system is AI-assisted triage, which can be used to generate summaries and provide additional context for findings. While not required for core functionality, this feature enhances usability by making results easier to interpret and providing additional insight into vulnerabilities.

Challenges and Solutions

One of the main challenges I encountered was parsing the XML output generated by Nmap. The structure of the data is complex and nested, which made it difficult to extract only the relevant information in a clean and consistent format. I addressed this by building a dedicated parsing module that converts the XML into structured Python objects, making it easier to work with in later stages of the pipeline.

Another challenge was designing a risk scoring system that is both meaningful and interpretable. I needed a way to prioritize findings without making the system overly complicated or opaque. I approached this by creating a deterministic scoring model based on known high-risk services and common misconfigurations, and then refining it through testing.

I also found that implementing historical tracking and trend analysis required careful consideration of how data should be stored and compared over time. To solve this, I designed a report storage system organized by IP address and timestamp, which made it possible to efficiently compare scans and identify changes in security posture.

Future Development

A direction I am interested in exploring is enabling Perimeter to be used as part of larger, automated systems, particularly those involving AI agents. Rather than functioning only as a standalone command-line tool, Perimeter could be extended into a service that exposes its capabilities through an API or lightweight interface.

This would allow external systems or AI agents to programmatically initiate scans, retrieve structured analysis results, and incorporate those results into broader workflows. For example, an AI-driven system could use Perimeter to continuously monitor a network, interpret changes in security posture, and make higher-level decisions based on that data.

I am also interested in deploying Perimeter across multiple pieces of hardware, such as small embedded systems or distributed nodes, allowing it to operate as part of a larger, decentralized monitoring network. In this model, individual devices could perform localized scans and send results to a central system for aggregation and analysis. This would make the tool more scalable and applicable to real-world environments where monitoring is distributed rather than centralized.

Overall, this direction would shift Perimeter from a standalone analysis tool toward a more flexible and extensible component within larger security and automation systems.

Conclusion

Perimeter represents an effort to move beyond raw data collection and toward meaningful interpretation in the context of network security. By combining established tools like Nmap with custom analysis and tracking capabilities, it demonstrates how software can be used to simplify complex technical processes and support better decision-making.

The project reflects my broader interest in cybersecurity, systems design, and practical problem-solving. It also serves as a foundation for future work in developing tools that make security analysis more accessible, scalable, and effective.
